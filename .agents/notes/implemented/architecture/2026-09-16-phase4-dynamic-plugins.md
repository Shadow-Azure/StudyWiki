# Agent Note: Phase 4 动态化装载与 guard 收权

Status: implemented

[English](2026-09-16-phase4-dynamic-plugins.en.md) | 中文

## Problem

Phase 1–3 建成的是"持久生态"：npm 供应链 + 封闭契约目录 + 重启生效（[Phase 2 Note](../../implemented/architecture/2026-09-11-phase2-external-plugins.md) 以重启换正确性，欠账三笔：清单一致性、失败回滚、多窗同步）。Phase 4 方向已由 [pr15 检视 §6.11](../../../../plans/2026-09-13-pr15-review.md) 拍板：动态化 + guard 安全补强必做。落到现状上有四个具体痛点：①外置插件改代码、开关、安装、移除全部要重启 app，作者与用户的调试内环被"重启"砍断；②boot 的 50ms 全树静默审计只覆盖启动装载，任何运行期装载都绕开审计；③inject 声明是君子协定——外置插件的 apply 拿真 ctx，没声明的服务照样摸得到，门面不等于边界；④将来 AI agent 写插件（用户拍板 2026-09-16 不进本阶段，另行开发）一旦上马，"陌生代码随时进 app"会成为常态，没有版本史就没有兜底回退能力。本阶段把动态化的最小完整闭环做出来：持久化版本仓 + 面板单入口全即时化 + guard 白名单门面 + 运行期激活审计，同时把"怎么写插件 / 怎么动态加载"两份常驻文档补齐，为后续 agent 阶段留好地基。

## Decision

范围（2026-09-16 用户逐项拍板）：**版本仓完整语义（多代 + 持久化）+ 热路径全量即时化（重载/启停/安装/移除，范围 C）+ guard 只包外置 + fiber 等待式审计 + docs/plugins/ 新文档两份（三件套）。AI agent、运行期网络豁免、密钥存放、跨窗热同步、同进程真沙箱不进本阶段；skill 暂缓（两份文档按 agent 可直接消费的口径写，将来 skill 只是它们的封装）。**

1. **持久化版本仓（快照仓 + 回滚写回）**：`plugins/<name>/` 活目录保持现状（boot 路径、封闭契约、安装管线零改动）；新增 `plugins/.history/<name>/<时间戳>-<sha256前12位>/`，每代存 `package.json + 入口源码 + meta.json`（创建时间、npm version、apiVersion）。版本产生点单一：**每次成功激活后快照**——Rust 新增 `snapshot_plugin_version` 命令，在 boot 激活、热重载、安装即激活三条路径的"审计通过"之后统一调用；内容 hash 去重（同代码重复激活不增生新代）；每插件保留 10 代，超出裁最旧，同一秒内的分代按递增戳排序（`created_at` 严格单调）。回滚 = 面板选历史版本 → `restore_plugin_version` 复用原子替换管线写回活目录 → 启用行随即热重载激活（停用行只落盘，下次激活时生效） → 成功后快照因 hash 去重指回同一代。移除插件连带删历史（面板确认文案注明），避免同名重装后历史复活。
2. **热路径全即时化（本窗生效、他窗重启见）**：新增 `src/loader/activate.ts` 共享激活函数（装载校验 → guard 包装 → ctx.plugin → fiber 等待式审计 → 快照），boot 的 ext: 行与全部热路径共用。四条热路径：**重新加载**（重读源码过 blob 缝，全绿才 dispose 旧 fiber 激活新 fiber——先验证后切换，失败旧版原地不动、行内报错）；**启停即时化**（fiber.dispose / 重新激活 + 写清单）；**安装/导入即激活**（管线落盘后自动写清单 enabled 行 + 本窗激活，失败转坏行——目录与清单保留、面板点名、下次 boot 重试；落清单行同时修掉 Phase 2 遗留缺口——此前经面板装的插件没有清单行，重启后不会被装载）；**移除即时化**（dispose + 删目录 + 删清单行 + 删历史，一次完成）。并发纪律：同一插件的操作按 `Map<name, Promise>` 链串行排队（dsh starting 表的等价物），防连点交错；共享激活函数自身不进队列（reload 在自己的串行块里调它，嵌套同键必死锁），安装路径显式包一层 `serialized`。清单仍是跨窗一致性准源：面板改动即写清单，他窗下次 boot 自然跟随；面板删"重启生效"提示，加常驻说明"改动仅本窗口即时生效，其他窗口重启后跟随清单"。
3. **guard 白名单门面（只包外置）**：新增 `src/loader/guard.ts`，照 dsh `cordis-client-runner/guard.ts` 的 Proxy 模式移植。外置模块过完形状校验后包装：apply 收到的 ctx 换成门面 Proxy——只放行 inject 声明过的服务名（生命周期动词白名单经落地核减：内置插件、宿主服务与生成模板零调用点，收窄即更安全）；读未声明的服务抛教学错误（点名"在 inject 里声明 'xxx'"）；禁止赋值；服务方法直接返回的 cordis Context（含 promise 解出的返回值）拒绝——嵌在容器里的不深扫。内置插件不包（一等公民，静态表直装）。**边界诚实化**：门面收窄的是服务面，不是语言能力——外置插件仍能触达 DOM/fetch/全局对象，docs 与本 Note 如实写明"这不是沙箱，同进程真沙箱仍在停机坪"。`verify:layering` 配套扫描：`ctx.plugin(` 只允许出现在装载器两文件，且 activate.ts 必经 `guardExternalModule` 包装。
4. **运行期激活审计**：热路径以 fiber 等待式审计替代 boot 的 50ms 固定静默——ctx.plugin 后轮询 fiber.state（10ms 间隔、2s 上限），到 ACTIVE 才算成功；超时或报错 dispose 半成品 fiber，按路径分治（重载保旧版 / 安装转坏行）。**声明服务缺席的等待态不单设面板态**：2 秒上限一到即转失败行，文案点名"声明的服务未提供"，不静默卡死。boot 的 50ms 审计继续只管内置行。
5. **面板（plugin-manager）改造**：外置行可展开版本历史（短 hash + 时间 + npm version + 是否当前），行操作：重新加载 / 回退到此版；行状态三源投影扩为四源（加本窗运行态）：运行中 / 已停用 / 装载失败（原因）/ 待清理（坏行只留移除——重载与历史仅在健康行出现，坏目录本就装载校验过不去）。
6. **Rust 命令面新增**：`snapshot_plugin_version` / `list_plugin_versions` / `restore_plugin_version` 三命令（文档注释齐备 → `pnpm gen:commands` + record:i18n）；hash 用 sha2（依赖已在）；安装/导入管线成功后前端在激活成功回调里调快照，Rust 侧零侵入既有路径。
7. **文档两件套（docs/plugins/，三件套 + 预算登记）**：`contract.md`（**怎么写插件**——动态化时代的单文件契约：name/apply/inject 三件套、inject 即权限声明、门面下什么够不着、失败处置与坏行语义、apiVersion）；`dynamic.md`（**怎么动态加载**——热重载/版本仓/回退/启停/移除的行为契约、本窗生效他窗重启见、审计语义、guard 边界诚实声明）。`authoring.md` 最小修补互链（npm 供应链视角不变）；`docs/architecture.md` 数据流段外置插件一句最小更新 + code-map 重生成。`plans/2026-09-13-phase4-worklist.md` 主体方向段勾掉对应项（W1/W2 启动性能项不在本 Note 范围）。
8. **门禁与环境无关**：零新增 npm/Rust 依赖（dep-audit 白名单不动）；全程离线零网络（豁免登记不动）；发布产物行为变化仅在面板与装载路径，`verify:release` 全档跑通。

## Alternatives considered

- **指针化版本仓（dsh 原样搬）**：活目录不存代码、清单记 activeVersion 指针、boot 从版本仓读。要动封闭契约、boot 装载路径、安装管线三处，且插件目录不再自包含（手动备份/分享拿到空壳）。磁盘做单一事实源、版本仓做只增历史更简单，dsh 指针化是因它的一切只活内存，不得不以仓为源。
- **dsh run/update 双指针 + mode 互斥完整语义**：磁盘单一事实源下"写回即切换"已覆盖全部场景（当前版 = 活目录内容，切版 = 写回+重载一个动作）；双指针要加清单字段与面板状态机，复杂度买不到对应场景。留真实痛点触发再补。
- **dsh 闭包求值 + CSP unsafe-eval**：pr15 §6.11 已拍板不搬；blob 装载缝（源码字符串→真 ESM 模块）语义更强且不碰 CSP。
- **跨窗热同步（他窗也即时）**：Phase 2 三难（清单一致性/失败回滚/多窗同步）的最简正确解仍是他窗重启见；面板单入口窄形态收敛，不在本阶段重开。
- **安装维持重启生效（Phase 2 裁定不重开）**：当时缺回滚与一致性兜底；版本仓 + 先验证后切换 + 坏行分治三件落地后，安装即激活的失败态有处可去，用户 2026-09-16 拍板重开（范围 C）。
- **内置插件同过 guard 门面**：一致性更好但对内防自己无意义，且要改全部内置插件的 ctx 用法，改动面与回归风险大；信任分级（内置全权 / 外置门面）本身成立。
- **同进程真沙箱（iframe/worker 隔离等）**：停机坪维持。门面交付的是纪律与可审计性，不是 containment；文档如实披露，不留"已经安全"的错觉。

## Consequences

- 外置插件生态从"重启生效"变"即时生效"，作者内环与用户体验断点消除；清单升级为本窗写、他窗读的最终准源。
- 版本仓是 append-only 数据，不自动激活任何东西——重启后唯一激活依据仍是清单 enabled 行，回滚永远是人（或将来的 agent）的显式动作。"重启即干净 slate"的性质由清单开关保住。
- guard 门面是 API 纪律不是安全边界：动态化把"真有恶意插件治理需求"从停机坪前提变成现实需求，本阶段交付收窄的服务面 + 教学错误 + 审计可见性；真沙箱欠账仍在，见 Alternatives。
- 欠账清单（后续阶段）：跨窗热同步；同进程真沙箱；agent 阶段四前置硬点中的两件（运行期网络豁免、密钥存放）随 agent 一起做；schema 化 config 校验（zod 基建已在宿主）；版本 diff/标注等版本仓深加工。
- 文档两件套按"AI agent 可直接消费"口径写（契约先行、示例可用、失败文案点名），将来产品内置 agent 的插件写作能力 = 读这两份文档 + 面板命令面，skill 只是封装。
