# Agent Note: llm-wiki 编译式知识层落地

Status: implemented

[English](2026-10-18-llm-wiki.en.md) | 中文

## Problem

agent 已有通用读写、检索与审批能力，但知识仍散在原文和对话里：重复阅读、源变更后的新旧结论、以及后续视频时间戳问答都缺少一个可验证的编译层。知识层必须说明 schema 放在哪、agent 如何收到契约、程序如何判定源状态、派生索引如何避免人工漏登记，以及移动源如何不重分析地保留产物。

## Decision

- schema v1 放在 `app-wiki` 插件内发布，不复制到库内；同版本、同插件集得到同一 LLM 行为契约。
- `AgentService.registerPromptSection` 提供 id 覆盖、按注册序拼接和注销函数；schema 追加在库约定之后。
- ingest/query/lint 保持对话驱动，agent 只用既有 read/grep/write/edit 工具维护 `.study-wiki/llm-wiki/`。
- 机器索引与 LLM 维护层分离：`.study-wiki/index.yaml` 是程序独占数据文件，`llm-wiki/` 是可读 wiki 产物，raw/ 产物留给 m3。
- index.yaml 采用固定字段、LF-only 的受限 YAML 子集；不新增 yaml 依赖，解析失败按损坏处理，并在源被打开时从该源的产物证据重建行。可选 `page` 字段记录 sources 页路径，使源迁址后的索引行在后续刷新中仍有稳定绑定。
- 源状态判定固定为同路径 fresh/stale、同内容哈希 moved、其余 unknown；路径先于哈希，避免移动后的重复登记抢先。
- `probe_source_file` 在授权根内流式计算 SHA-256；known size+mtime 命中直接复用哈希，未命中才重读内容。
- `write_text_file` 自动创建父目录，使 agent 能写入新 concepts/entities 深路径，同时保留文件组件冲突失败。
- 索引采用活动源惰性物化：只有源被打开（或 `sourceState` 显式请求该源）时才探测该源并更新它自己的索引行，其他行原样保留。sources 页优先按 `<源相对路径>.md` 直取；仅 moved 旧页缺 `page` 绑定或未知源没有约定页时才回退扫描页面树。无活动文件时不扫描、不探测、不改写索引；无产物时不创建空行，无 probe 也不写空哈希。
- 文件树路径经 `pathe` 统一为 `/` 规范形状：`toRel`、sources 根相对路径和 probe 缓存键都走同一套 Windows/POSIX 语义，不再依赖字符串前缀切片。索引只保存库相对路径，因此跨平台时仍指向同一源与 sources 页。
- moved 把 path 重指为新位置并保留页面绑定；后续刷新优先按 `page` 认出同一产物，保留 artifact/analyzedAt 与有效哈希，不因页面 frontmatter 暂指旧路径而回退。源在迁址后再次变化时仍按哈希不一致判 stale，不会把新内容直接刷成 fresh。
- `ctx.wiki` 构建上下文时只处理当前打开文件：换根清空 probe 与路径缓存，打开文件不再全量失效；插件卸载时同步注销 prompt 贡献段。

## Alternatives considered

- 机器索引用 markdown + YAML 围栏：文档包装易被误编辑，改纯数据 `index.yaml`；`index.json` 人读性更差，未选。
- schema 放库内文件：库副本会漂移，且违背同版本行为一致，否。
- 专用 wiki_ingest/query/lint 工具：开放性写作难以参数化，并推翻通用工具面共识，否。
- 独立 wiki 插件加任务队列与向量索引：过度工程，向量索引也撞环境无关硬约束，否。
- 每回合扫描全部 sources 页并重哈希所有已分析源：能保持全量索引即时一致，但会把打开一个小笔记的成本放大到整个资料库，否。
- 程序性骨架初始化：程序会获得 wiki 页面模板知识；改由 agent 依 schema 首写，契约只归 schema，未选。

## Consequences

- #31 与 #34 的索引契约合并：#31 先落 `index.yaml` 与内容哈希，#34 后续专注 raw/ 产物与字段扩展，其「md5/index.md」文案改为「内容哈希/index.yaml」。
- m4-01 依赖 sources 页主题对照与 raw topics；m4-02 依赖 frontmatter、wikilink 和 log 追加语义。
- 欠账：ingest 批量写入仍是逐文件审批卡；机械 lint、schema override 合并通道、同证据/同哈希冲突 tie-break 未落地；插件 teardown 只验证主路径，尚未逐通道断言事件、prompt 注销与缓存清理。
- 打包冒烟暴露的两个 P1 已由服务级回归覆盖：真实递归树中的嵌套 sources 页，以及跨服务重启的 moved 持久性；moved 后再变更的内容另有 stale 回归。
- Windows 形状路径另有服务级回归：同一 fake 同时钉住索引 `path`、sources 页 `page`、无 frontmatter 时的 source rel 推导与活动源状态。
- 惰性索引回归覆盖三条边界：活动 A 时不探测未打开的 B 且保留 B 行；无活动文件时零扫描/零 probe/零写入；`file-opened` 后已打开源仍复用 known size+mtime 样本。代价是未打开源的索引行会保持上次值，直到该源被打开时刷新。
- 外置插件契约措辞已校正：`inject` 是 Cordis 依赖声明，不是权限或沙箱；`agent`/`wiki` 仍是内置内部服务，不进入已承诺的外置 API。显式服务名 allowlist 与成员白名单属于后续 API 决策，本 PR 不以 `inject` 冒充权限。
- 接受索引损坏的历史边界：`index.yaml` 同时保存 stale 判定所需的旧哈希；文件损坏或删除后，只能从现存 sources 页用当前内容哈希重建，分析后已变化的源可能被重新登记为 fresh。2026-10-18 决定不引入 per-source meta 并列账本，接受该极端场景的精确性损失，以保持索引格式与 agent 页面边界简单。
