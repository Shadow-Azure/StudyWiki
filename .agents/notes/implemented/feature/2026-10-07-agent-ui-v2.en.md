# Agent Note: Agent panel UI v2: turn process folding and composer approval takeover

Status: implemented

English | [中文](2026-10-07-agent-ui-v2.md)

## Problem

The m2-03 agent panel floods the transcript with one card per tool call and stacks four control groups (session dropdown, approval toggle, default-mode dropdown, model dropdown) in the header; approvals arrive as bulky cards inside the chat. A live MiniMax run confirmed the noise buries conclusions, pending approvals lack visual weight, decided cards keep hogging space, and "session mode" vs "new-session default mode" read as duplicates.

## Decision

Following the dsh Web UI (`ui-chat` turn folding, `ui-approval` composer takeover, `ui-model-selection` composer seat) and blending codex TUI (`approval_overlay.rs`: action-shaped options, Esc always cancels) plus Claude Code (`PermissionPrompt/PermissionDialog`: input takeover + detail popover above), we rebuilt the UI inside the `app-agent` plugin only (no `agent-core` surface changes):

1. **Turn process groups**: `tool-start/tool-end` append into the active group's collapsible body; the running summary shows "正在执行 <tool>"; `turn-end` settles to "已完成 N 个动作 · duration" unless focus stays inside; `aborted/error` settle too so groups never dangle. History renders from `assistant.toolCalls` (`SessionLine` has no separate tool-result line, so result content is not persisted), with placeholder text "历史记录未含结果内容".
2. **Approval takes over the composer**: approvals no longer insert transcript cards; the composer moves through three states (normal → approval → decided). Approval state gets a cinnabar outline, a one-line request summary, and a bottom row with "查看详情 ▾ / model pill / 批准 ⌘⏎ / 拒绝 Esc"; the detail popover anchors above the composer (path, change size, diff, grant-scope note); `.agent-panel` is the `position: relative` context for these popovers so coordinates do not escape to the three-column `.body`. A decision appends a one-line `renderDecisionLine` record, the composer passes through decided and restores the saved draft; multiple approvals queue and present one by one. The `aborted` event clears the active and queued approvals, removes the detail popover, cancels delayed presentation, and returns the composer to the user so an invalid request cannot remain actionable. Esc layering: built-in modals register in the window-level `ActiveLayerStack`; while a layer exists, Agent shortcuts yield and queued approvals resume after it closes; otherwise → deny the active approval.
3. **Single-row header**: title + status dot + new/history/more; the history popover supports search (`paintSessionOptions` filters by title), the model picker moved into a composer pill menu grouped by endpoint, and the new-session default mode moved into "more"; the current-session approval mode adapts to composer width—a wide composer shows a "请求批准 / 帮我批准" segmented control, while a narrow one collapses to a 24px icon with full options in a popover. Errors became closable toasts (5s auto-dismiss); a composer status line reflects turn state driven by events (`turnRunning`) instead of the `session.running` snapshot.
4. **Queued drafts while running**: when a turn is running and the composer has a submittable draft, the primary button remains "send" and places the message in a queue dock above the composer; with an empty draft, the primary action yields to "stop". One queued item shows its preview directly; several collapse behind a count and expand on demand. Each item has "remove", which deletes only that queued draft. When the active turn completes, drafts leave the queue FIFO. "Stop" interrupts the active turn and clears unsent drafts, so removing one queued item is never conflated with interrupting the turn.

## Alternatives considered

- **Keeping the transcript approval card** (m2-03 shape): decided cards keep hogging space and compete with the content being read — replaced by composer takeover.
- **Keeping the header model dropdown**: two adjacent selects with near-identical semantics; model switching happens "right before sending", so the composer seat matches the dsh/claude mental model.
- **A synthetic `type: "tool"` history line**: `SessionLine` has no such type; faking it in tests would hide the real contract that tool results are not persisted — history now renders from assistant.toolCalls.

## Scope

`src/plugins/app-agent/{index,render}.ts`, `src/plugins/{plugin-manager,llm-settings}/index.ts`, `src/ui/active-layer.ts`, `src/styles.css`, `tests/app-agent*.ts`, `tests/active-layer.test.ts`, `tests/ui-preview.test.ts`. The `agent-core` service interface, approval protocol, and JSONL persistence are untouched. Queued drafts while running also live only in the `app-agent` panel and do not extend the service protocol. Final interaction design and the hi-fi preview live in `plans/2026-10-07-agent-ui-dsh.md` and `plans/agent-ui-preview-v2.html` (issue #52).

## Consequences

- Benefit: settled turns show only a conclusion and duration by default; approvals complete inside the composer with details on demand; header controls regain a clear hierarchy.
- Cost: the `app-agent` DOM state machine and event wiring are more complex; historical action results can only show the placeholder permitted by the persistence contract.
- Debt: approval-detail rule guidance still comes from current request fields; if guardian later provides finer grant scope, the protocol and popover must grow with it.
