# 图示（SVG）制作规范

## 何时必须配图

满足任一条件即**必须**配至少一张：

- 变更涉及 ≥3 个模块的数据流或调用链
- 有状态机（≥4 个状态或有非平凡转移条件）
- 并发/流式/多窗口时序
- before/after 结构对比能显著降低理解成本
- 用户操作路径超过 5 步

其余情况可选。没有图时不要硬凑。

## 图类型选择

| 场景 | 图类型 | 要点 |
|---|---|---|
| 用户操作路径 | 流程图（泳道） | 用户/系统两条泳道，箭头标动作与响应 |
| 模块关系 | 组件图 | 方框=模块，箭头=调用/数据方向，线上标方法名 |
| 数据流转 | 数据流图 | 标注每一步的数据形状（不必精确类型，说形状） |
| 状态机 | 状态图 | 圆角框=状态，边=触发条件+副作用 |
| 时序（流式/并发） | 时序图 | 垂直生命线，水平箭头按时间序，标序号 |
| 架构对比 | before/after 双栏 | 同一坐标系并排，变化处用强调色 |

## SVG 制作标准

- **手写 SVG 文本**（AI 直接产 SVG 源码），不依赖任何渲染工具或外链
- viewBox 宽 ≤1000；中文标签字号 ≥13；整图在浏览器 100% 缩放下可读
- 配色跟随站点令牌近似值：主色 `#5454d4`（暗色 `#9a9af5`）、成功 `#2da44e`、危险 `#cf222e`、中性灰阶；底色透明
- 文字必须可选中（用 `<text>`，不要把字转成路径）
- 连线箭头统一；避免交叉；同类元素同样式
- 图内不写代码，只写模块名/状态名/动作名

## 存放与引用（易错，严格照做）

1. 存放路径：`walkthrough/assets/<issue-slug>/<图名>.svg`（slug 与 changes 页一致）
2. 在 yaml 的 markdown 字段里引用（feature/design/userFlow 步骤间均可）：

```markdown
![数据流](../assets/<issue-slug>/flow.svg)
```

**路径必须以 `../assets/` 开头**——渲染后的页面住在 `dist/changes/`，构建器会把 `walkthrough/assets/` 原样复制到 `dist/assets/`。写成 `assets/...` 或绝对路径都会 404。

3. 图下方加一行斜体说明（图不能自解释时）：`*图 N：<一句话>*`。这句话由该图专属的独立 subagent 依据真实变更和相邻叙事生成，主线程再统一收口写入 yaml。

## 发布前检查

- [ ] 每张图在 `dist/changes/<slug>.html` 里真实加载（本地打开看一次）
- [ ] 中文无乱码、无溢出 viewBox 的文字
- [ ] 图内模块名与正文术语一致（同一东西不写两个名字）
- [ ] 每张图都有独立 subagent 返回的讲解草稿与证据；主线程完成图题、术语和正文一致性校验
