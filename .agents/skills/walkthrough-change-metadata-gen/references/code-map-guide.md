# 代码地图与逐段检视注解规范

## attention 分诊

| 等级 | 判定 | 例子 |
|---|---|---|
| must-read | 新语义/改语义的核心路径：状态机、安全边界、错误处置、并发时序、数据一致性、公共契约 | 回合循环、权限校验、SSE 解析、原子写、对外 API |
| skim | 支撑性变更：测试、文档、样式、构建脚本、纯接线 | spec 文件、文档三件套、CSS、CI 接线 |
| skip | 机械产物：配对记录、生成区、锁文件 | `*.i18n.yaml`、`docs/commands.*`、`pnpm-lock.yaml` |

**分诊纪律**：

- 机械路径禁止标 must-read（门禁强制）
- 拿不准往上调一级——检视预算花在真语义上，但漏掉真语义的代价更高
- 每组必须有 `why`（为什么这组这样分诊），一句话即可

## 分组

按**叙事角色**分组，不按目录。推荐组序（渲染按此优先展示）：

1. 语义核心（must-read）：这个 PR 的"心脏"
2. 契约与边界（must-read 或 skim）：对外面、错误面、安全面
3. 支撑与测试（skim）
4. 文档与机械伴生（skim/skip）

组名用中文短语说清角色（"回合状态机与落账"优于"agent-core"）。

## 逐段注解（changes[]）

**每段 = 一次有意义的变更语义单元**，硬性约束：

- snippet ≤20 行（门禁强制）；从当前源码逐字复制；YAML 块标量会剥统一缩进，顶格复制即可（定位按整行 trim 归一化）
- note 讲"这段在做什么、为什么这么做/起什么作用"，2-4 句；**禁止逐行翻译代码**
- 每段聚焦一件事；一个函数里有两件事就拆两段
- 优先锚定：公共出口、状态转移、边界分支、错误路径、并发点；跳过：纯样板、重复结构

**成对生成纪律**：

- snippet 与 note 在同一个判断里写好，禁止先把源码切成片段列表、再另起一轮批量写 note 后按位置拼接。
- snippet 必须自包含且唯一。孤立 `}`、`});`、单行 `/** ... */` 或半个函数都不是语义单元；把声明、关键分支或相邻上下文一起带上。
- note 必须在同一文件内唯一，并点名本段符号、状态转换或边界。把 note 原样移到相邻段仍然成立，就是通用套话，必须重写。
- 同一文件出现重复 snippet 时，不要依赖“第一次匹配”；扩展上下文直到能唯一指向目标语义。

**覆盖率口径**（门禁）：must-read 组源码文件的新增行中，被注解锚定区间覆盖的比例 ≥90%。机械尾部（纯 CSS 行、生成注释）覆盖不到可留缺口，但优先补语义段而不是申请豁免。

**保存前逐段复核**：按 `snippet 首行 → note` 顺序从头读一遍。若某条 note 无法指出 snippet 正在做什么，或两条 note 互换后仍读得通，该段未完成。

## 自证陷阱（必须自知）

写代码的 AI 标"哪里可以不细读"存在利益冲突。缓解纪律：

1. 机械路径由门禁强制归 skim，AI 说了不算
2. 语义文件被低估（该 must-read 标了 skim）时，你在 reviewGuide.order 里看不到它——**生成后自查一遍 order 列表是否覆盖所有语义核心**
3. 拿不准的判断写进 risks，点名请人仲裁，不要静默降级

## reviewGuide

- **order**：3-6 个文件/主题，按"先建立心智模型，再看边界"排序；每项一句"看什么"
- **risks**：1-3 条真实风险（安全/状态/并发/一致性/兼容），每条带"如果错会怎样"；没有就写"无已知风险"并说明验证依据
- **acceptance**：issue 验收条目逐条映射到可跑证据（测试文件/命令/人工步骤）；证据必须真实存在

## verification

只写真实跑过的命令与结果（如 `pnpm test 81/697 绿`）。没跑过的不写；写"未跑"也是合法记录。
