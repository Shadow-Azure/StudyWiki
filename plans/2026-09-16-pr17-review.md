## 这个 PR 想合入什么

PR #17 要解决的不是“给按钮涂色”这种局部美化，而是把一个零样式原生控件组成的学习客户端，变成有视觉秩序的工作台：工具面紧凑安静，阅读面像书页，图标不依赖字体 glyph，深浅主题跟系统走，后续 UI 改动有一套令牌可依。

打个比方：旧界面像一张只有台面的桌子，浏览器给什么控件就用什么控件；这个 PR 先做了一盒**涂料色卡**（CSS 变量令牌）、一套**印章**（内联 SVG 图标库）和一张**可调书架的书桌**（顶栏 + 可拖宽侧栏 + 阅读主区），再搭了一间**样板间**（`preview.html` + `src/preview.ts`），以后改 UI 不用先启动 Tauri 才能看整体效果。第二个提交又把应用图标统一成冰山品牌，并让编辑面和预览面共享同一套书页度量。

读完后应能回答三个问题：它解决“长时间阅读不舒服、UI 无章可循”的问题；做法是无框架 CSS 令牌 + vanilla DOM 原子件 + 生产插件复用的浏览器预览；代价是样式与 DOM 契约要同步维护、CodeMirror 多一个直接依赖、无障碍和发布图标还剩几处需要拍板的小账。

## 2. 架构导览

### 2.1 令牌层：先定语言，再画界面

`src/styles.css` 用两组变量描述同一套语义：浅色 `:root` 是纸面（`src/styles.css:7-50`），深色 `@media (prefers-color-scheme: dark)` 是墨面（`src/styles.css:52-79`）。变量不是按颜色位置命名，而是按用途命名：`--chrome` 工具面、`--paper` 阅读面、`--raise` 浮层、`--hairline` 发丝线、`--ink` 三阶文字、`--azurite` 交互、`--cinnabar` 警示/未保存。

这让主题切换不需要 JS 分支：同一个选择器引用变量，系统偏好改变量值。也就是说，主题是“涂料换批号”，墙的位置和家具布局不动；这符合仓库环境无关约束里“同一版本行为一致、无运行时分支”的取向。

### 2.2 工作台壳：三列语义与可调书架

壳仍是 app-shell 一个插件负责，不引入 UI 框架。顶栏 DOM 从“左操作 + 标题”变成“品牌 / 居中活动文件名 / 右操作”（`src/plugins/app-shell/index.ts:37-52`），对应 CSS grid 三列（`src/styles.css:150-206`）。

侧栏可调的核心是 `.body` 上的 `--sidebar-size`（`src/styles.css:138-146`）：拖拽或键盘只改这个变量（`src/plugins/app-shell/index.ts:65-102`），grid 和 resizer 位置跟着变。resizer 本体是绝对定位的 7px 命中区，视觉上是 1px 发丝线（`src/styles.css:216-246`），所以拖拽热区比看见的线宽，操作更稳。210–380px 边界与 Tauri 720px 最小窗口（`src-tauri/tauri.conf.json:16-19`）匹配，避免最窄时主区被挤爆。

空态分两级：无 root 显示欢迎页；有 root 但未选文档显示“从左侧选择一篇文档”的次级提示（`src/plugins/app-shell/index.ts:110-152`）。这补的是真实使用中的空白断层，而不是装饰。

### 2.3 图标与按钮：保住 textContent 契约

`src/ui/icons.ts` 把图标表达成 `ICONS` 数据表（`src/ui/icons.ts:11-61`），再由 `icon()` 统一 `createElementNS` 构造 SVG（`src/ui/icons.ts:70-86`）。SVG namespace URI 是 DOM API 的标识符参数，不是网络资源（`src/ui/icons.ts:6-8`）；环境无关门禁已登记豁免。

选择显式构造的原因记录在 Note：WKWebView 不绘制由 `div.innerHTML` 解析出的 SVG，而静态标记与 `createElementNS` 正常。图标元素 `aria-hidden` 且不产生 `textContent`，所以树行仍能保留“文件名 span 精确断言”，测试契约不被视觉改造冲垮。

`labelButton`（`src/ui/dom.ts:17-25`）负责按钮的公共机械动作：创建 button、放图标、可选文案、类名与可访问名；点击监听仍归调用方，避免工厂偷偷吞业务。相当于把七份手写按钮样板收成一枚印章。

### 2.4 文件树：结构、活动状态与 Windows 根名

树头显示根目录名，`rootLabel()` 同时按 `/` 与 `\` 切分并取最后一个非空段（`src/plugins/view-filetree/index.ts:12-13`），因此 Windows 路径不会把整串 `C:\Users\...` 塞进小标题。目录行带 chevron 与 `aria-expanded`，文件行带类型图标，活动行加 `tree-row-active` 和 `aria-current="true"`（`src/plugins/view-filetree/index.ts:50-75`）。

刷新从文字按钮变成图标按钮，但行为仍是 `reload()`（`src/plugins/view-filetree/index.ts:37-45`）。树本体的过滤与铺平纯函数没有改，说明这次是展示层手术，数据逻辑没有搬家。

### 2.5 Markdown：阅读面与编辑面同一本书

预览和编辑共享 760px 度量、17px 阅读衬线和相近行高：预览由 `.markdown-body` 控制（`src/styles.css:451-549`），编辑由 CodeMirror theme 控制（`src/plugins/doc-markdown/editor.ts:26-37`）。工具条改为显式分段控件，两个按钮各自 `aria-pressed`（`src/plugins/doc-markdown/index.ts:78-102`），保存按钮用红点表示脏态并声明 `aria-keyshortcuts`（`src/styles.css:439-447`）。

CodeMirror 从 `basicSetup` 改为 `minimalSetup`（`src/plugins/doc-markdown/editor.ts:72-78`）。本地安装的 `codemirror/dist/index.js:78-94` 明确 `minimalSetup` 只含特殊字符高亮、历史、选区绘制、默认高亮和默认/历史键位，不含行号与折叠 gutter；新增测试也断言 `.cm-gutters` / `.cm-foldGutter` 不存在（`tests/doc-markdown-editor.test.ts:5-17`）。这让编辑器从“代码编辑器嵌进文档”变成“文档的另一面”。

`@lezer/highlight` 被提升为直接依赖，用于 `tags` 类型化高亮契约（`src/plugins/doc-markdown/editor.ts:6`、`39-54`）。npm/GitHub/tarball 实测：上游为 `lezer-parser/highlight`，MIT，作者 Marijn Haverbeke；tarball 7 个文件、99.9KB unpacked，运行依赖仅 `@lezer/common`，无 `node:` 引用；它本来就是 CodeMirror 生态传递依赖，这里只是把直接 import 显性化。

### 2.6 槽位隐藏、视频暗室与插件面板

`main.viewer` 是多插件共用的槽位。Markdown 与视频在 kind 不匹配时现在各自 `host.hidden = true`（`src/plugins/doc-markdown/index.ts:72-77`、`src/plugins/doc-video/index.ts:18-20`），匹配的 viewer 显示、不匹配的隐藏，避免两个 slot 把视频推出视口。`tests/ui-preview.test.ts:39-41` 直接钉住 `[true, false]`。

插件面板是固定 overlay，补了 `role="dialog"`、`aria-modal`、Esc 和初始聚焦安装输入框（`src/plugins/plugin-manager/index.ts:25-46`、`123-125`）。Esc 监听挂 document 的原因写在注释里：面板整体重渲染会销毁焦点元素，焦点回落 body 后事件不再经过 overlay 子树（`src/plugins/plugin-manager/index.ts:37-40`）。错误行与重启提示跨 render 复用同一元素（`src/plugins/plugin-manager/index.ts:50-66`），避免 `replaceChildren` 把状态提示弄丢。

### 2.7 浏览器预览：样板间装的是真家具

`PreviewSlots` 复刻生产 `SlotsService` 的关键行为：每个 renderer 独立子元素、注册序渲染、mount 时重放（`src/preview.ts:39-72`；生产对照 `src/host/slots.ts:9-49`）。`mountUiPreview()` 用内存 `files/windows/plugins` 假宿主装载六个真实插件（`src/preview.ts:77-119`），再打开预览树中的 Markdown，等待一轮 microtask 让异步 read/open 完成（`src/preview.ts:121-123`）。

关键是“真插件 + 假宿主”，而不是另写一套演示 UI。样式、DOM、事件流与生产相同，只有 Tauri 命令边界被替换；因此它能发现 slot 顺序、隐藏、面板打开这类集成问题。构建实测 `dist/` 不含 `preview.html`，因为 Vite 发布入口仍是 `index.html`，`preview.html` 只在 dev server 显式访问。

### 2.8 环境无关与依赖面

唯一新增 URL 问题是 `SVG_NS = "http://www.w3.org/2000/svg"`。文档豁免表明确它是 `createElementNS` 标识符、永不联网（`docs/environment-independence.md:34-38`）；门禁 `ALLOWED_URL` 也加入 `http://www.w3.org`（`scripts/verify-env-independence.mjs:10-14`）。

依赖白名单同步加入 `@lezer/highlight`（`scripts/dep-allowlist.json`），`pnpm-lock.yaml` 只增加直接 importer 记录，没有引入新的包树。dep-audit、layering、env-independence 本地全绿。需要注意：当前扫描器按 host 前缀放行，豁免面比文档口径宽，见 §6.3。

### 2.9 品牌资产与文档收口

原生图标源头是 `src-tauri/icons/iceberg.svg`：1024 viewBox、圆角裁切、深海渐变、冰山水上/水下形体与水线（`src-tauri/icons/iceberg.svg:1-26`）。派生 PNG/ICO/ICNS 全部更新；`file` 实测 32/64/128/256/512/1024 与 Windows Square/Store 尺寸齐全，ICO 含 7 个尺寸，ICNS 为 macOS icon。Tauri bundle 显式引用 32/64/512/ICNS/ICO（`src-tauri/tauri.conf.json:33-39`）。

文档收口是完整的：架构组成树登记 `preview.ts` 与 `ui/*`；Note 记录 UI 框架、DSH 三栏、CJK 网络字体、文字符号图标四个备选为何不取；双语 Note 与 environment 文档均重录。

## 3. 数据流走查（主线剧本）

**剧本：从样板间打开一篇 Markdown、编辑保存，再检查插件面板**

1. 开发者运行 `pnpm dev` 后访问 `/preview.html`；页面把 `#app` 交给 `mountUiPreview`（`preview.html:8-14`）。
2. `mountUiPreview()` 创建真实 `WorkspaceService`、`PreviewSlots` 和内存 files/windows/plugins 服务，再按 app-windows → plugin-manager → file-tree → markdown → video → app-shell 顺序激活真实插件（`src/preview.ts:77-119`）。
3. app-shell 挂载三处 slot 容器（`src/plugins/app-shell/index.ts:106-108`）。前五个插件已在对应 slot 注册 renderer，因此顶栏按钮、树、Markdown/video viewer 都被重放渲染。
4. `workspace.setRoot(previewRoot)` 触发 `root-changed`：树清空展开态并异步 `readTree`（`src/plugins/view-filetree/index.ts:97-101`）；app-shell 移除欢迎页，因尚未选文件插入次级空态（`src/plugins/app-shell/index.ts:134-145`）。
5. `workspace.openFile(markdown)` 触发 `file-opened`：树重渲染并给活动行 `aria-current`（`src/plugins/view-filetree/index.ts:50-75`、`:105`）；app-shell 顶栏显示文件名并移除空态（`src/plugins/app-shell/index.ts:148-151`）。
6. Markdown 插件读取内存文本，渲染 `.markdown-body`；视频插件同事件下隐藏自己的 slot（`src/plugins/doc-markdown/index.ts:120-140`、`src/plugins/doc-video/index.ts:15-27`）。
7. 用户切“编辑”：分段按钮更新状态并全量 render；旧 editor 销毁，新 CodeMirror 以文档主题挂载，onChange 进 `DocState` 记脏，Mod-S 走保存回调（`src/plugins/doc-markdown/index.ts:84-117`、`src/plugins/doc-markdown/editor.ts:62-89`）。
8. 保存成功写回并清脏；失败时在编辑器前插入错误条，用户可点 × 清除（`src/plugins/doc-markdown/index.ts:31-58`）。这里有一条待拍板的残留：失败后不点 ×、再次保存成功，旧错误条不会移除（§6.2）。
9. 点击顶栏“插件”：面板读取清单与扫描结果，三源合成行；安装/开关/移除失败走内联错误，成功显示重启提示（`src/plugins/plugin-manager/index.ts:67-124`）。Esc、关闭按钮或外点会移除 overlay 并解绑 document 监听（`src/plugins/plugin-manager/index.ts:37-49`）。

### 6.2 保存失败后未手动关闭，再次保存成功时错误条残留

- **问题**：磁盘/权限短暂恢复后，用户看到的红条会说失败，但脏点已消失、文件实际已保存，状态信号互相矛盾。

### 6.3 SVG 豁免在门禁中按整个 `www.w3.org` host 放行

- **位置**：`scripts/verify-env-independence.mjs:13-31`；登记口径在 `docs/environment-independence.md:37`；唯一正当使用在 `src/ui/icons.ts:8`。
- **现象**：文档豁免的是精确 URI `http://www.w3.org/2000/svg`，但 `EXTERNAL_URL_RE` 只捕获 host，且 `ALLOWED_URL.some(a => u.startsWith(a))` 会放行整个 `http://www.w3.org`。若未来源码或产物资源引用同 host 的其他 URL，扫描不会红。
- **问题**：环境无关硬约束的机械门禁比文档承诺宽，虽然当前代码无实害，但豁免面不该悄悄扩大。
- **不修的影响（通俗版）**：当前代码没有实际危害，因为只用了那个 SVG namespace URI。但门禁等于把“只允许进这一个房间”改成了“允许进整栋楼”；以后若有人不小心引入 `www.w3.org` 下的其他外部资源，扫描也不会拦住。
- **预判**：建议本 PR 收紧：让扫描器保留完整 URL 后按精确 URI 放行，或先特判 `http://www.w3.org/2000/svg`，再走既有 host 规则；同时保留文档与 Note 链接校验。改动小，能守住“唯一 home 与门禁一致”的原则。
- **结论**：✅ 2026-09-16 已修复于 `2c651a2`：源码扫描保留完整 URL，W3C 仅精确放行 `http://www.w3.org/2000/svg`，Tauri 本地/配置地址仍走既有前缀；dist `src/href` 判定共用同一函数。测试覆盖同 host 非豁免路径在源码与产物均拒检，PR inline thread 已回复并 resolved（`discussion_r4021309713`）。

### 6.4 `aria-modal` 面板没有焦点圈禁与关闭后焦点归还

- **位置**：`src/plugins/plugin-manager/index.ts:25-46`、`src/plugins/plugin-manager/index.ts:123-125`。
- **现象**：面板声明 `role="dialog"` / `aria-modal="true"`，打开后聚焦安装输入框，Esc 可关；但 Tab 可以跑到被 overlay 覆盖的背景 UI，关闭后焦点落在 body，不回到“插件”按钮。
- **问题**：对键盘/辅助技术用户来说，ARIA 语义说“这是模态”，实际焦点边界不是模态；这比视觉问题更容易造成迷路。
- **不修的影响（通俗版）**：鼠标用户几乎不受影响；键盘用户和读屏器用户会明显迷路。用户在面板里按 Tab，焦点却跑到被遮住的顶栏或文件树按钮上；关闭面板后焦点掉到 body，下一次 Tab 可能从页面开头走，原来的位置丢了。它不损坏数据，但“界面宣称模态、焦点却不是模态”是无障碍语义半成品。
- **预判**：不是数据损坏级阻塞，但属于无障碍语义半成品。可本 PR 补最小焦点圈禁 + 关闭归还，或降级为非 `aria-modal` 并开 fast-follow；考虑到面板控件数量少，最小 trap 大约几十行，不需要引依赖。
- **结论**：✅ 2026-09-16 已修复于 `d6c0448`：Tab/Shift+Tab 在面板可聚焦控件首尾循环；Esc、关闭按钮或外点关闭后焦点归还打开面板的“插件”按钮。键盘路径测试覆盖循环与 Esc 归还，PR inline thread 已回复并 resolved（`discussion_r4026056026`）。

### 6.5 浅色主题 `ink-3` 的低对比使用略低于宣称标准

- **位置**：`src/styles.css:21-25`；树/类型图标 `src/styles.css:307-313`；编辑器暗淡语法与格式符号 `src/styles.css:575-595`。
- **现象**：按 WCAG 相对亮度公式实测：浅色 `--ink-3 #8d96a2` 对 `--paper #ffffff` 为 2.99:1。作为树/类型图标，非文本图形组件建议至少 3:1，差 0.01；作为 Markdown 注释/meta/URL/formatting 等 17px 普通文本，建议 4.5:1，差距更明显。深色侧同 token 对纸面为 4.08:1，图形项达标。
- **问题**：提交信息写了“小字 AA 对比度（ink-3 → ink-2）”，但编辑器低层级 token 仍使用 ink-3；如果 AA 目标覆盖语法文本，当前未完全达到。
- **不修的影响（通俗版）**：视力好、环境光正常时问题不大；低视力用户、强光下或低质量屏幕上，灰色图标和暗淡语法文本会看不清。若产品承诺 WCAG AA，这就是合规缺口；主要伤害可读性，不影响功能。
- **预判**：不必全局牺牲三阶墨色层级。文本类 token（comment/meta/url/formatting）可改用 `--ink-2`（实测 5.81:1）；树图标可单独用 ink-2 或微调 ink-3 到 3:1。是否把语法暗淡文本纳入 AA，由维护者拍板。
- **结论**：＿＿＿

### 6.6 原生冰山图标缺少发布面肉眼验收记录

- **位置**：`src-tauri/tauri.conf.json:33-39`；`src-tauri/icons/iceberg.svg:1-26`；`src-tauri/icons/*` 18 个二进制修改。
- **现象**：`file` 实测所有派生文件尺寸/格式齐全，SVG 主图结构完整；但 WKWebView 页面截图不能验证 macOS Dock、Windows 任务栏/安装器、Linux 桌面入口中的 OS 图标。CI Rust lane 也不等价于人工看 bundled 图标。

- **不修的影响（通俗版）**：功能不会坏，风险是品牌观感翻车：16px 或 32px 时冰山可能糊成一团、边缘被裁掉，或某个平台的安装器图标风格不协调。属于发布质量与人工验收欠账，不是运行时缺陷。

### 9.1 `src/styles.css` —— 从 73 行应急样式到一套工作台语言（M，+755/−51）

**关键代码块对照**：

旧代码只有主题开关和局部组件样式：

```css
:root { color-scheme: light dark; }
* { box-sizing: border-box; }

.body { display: grid; grid-template-columns: 260px 1fr; min-height: 0; }
```

新代码先定义语义层：

```css
:root {

  --paper: #ffffff;
  --ink: #20242a;
  --ink-2: #5d6673;
  --azurite: #2563eb;

@media (prefers-color-scheme: dark) {
```

这不是“换个颜色”，而是把颜色绑定到用途：后续新增 UI 只能说“我是工具面/浮面/警示”，不能随手写裸色值。阅读面块（`:451-604`）用 760px、17px、衬线、行高 1.9、标题线和引用线构成书页感；编辑器块（`:551-604`）用同一度量，避免预览像书、编辑像终端。

**实现思路总结**：令牌承担一致性，CSS 原生特性承担主题和布局；无 JS 主题分支，发布环境行为保持确定。

### 9.2 `src/ui/icons.ts` + `src/ui/dom.ts` —— 印章与按钮模具（A×2）

**职责**：把重复且容易漂移的 SVG/按钮样板收成两个无状态工厂。**变更形态**：新增；旧插件里是文字符号（`▸ ▾ ▶ ●`）和手写 button。

**关键代码块对照**：

```ts
row.textContent =
```

### 9.3 `src/plugins/app-shell/index.ts` —— 壳从容器变成可调工作台（M，+92/−13）

新顶栏与可调侧栏：

**实现思路总结**：壳掌握布局状态，但只暴露一个 CSS 变量；插件仍不知道彼此，也拿不到布局实现。

**检视发现**：无新数据流问题；键盘/拖拽边界已被测试钉住。
